# Milestone 0.1.1 Quality Closure Spec

> 한국어 요구사항 경계: 이 spec/design/test-spec 문서는 한국어 독자가 요구사항을 추적할 수 있도록 목적과 검증 경계를 한국어로 보강한다. API 이름, command, code identifier, issue/PR 번호, compatibility matrix, acceptance keyword, DoD/test evidence는 요구사항 약화를 막기 위해 원문 그대로 보존한다. 변경자는 아래 literal contract를 삭제하거나 의미를 약하게 바꾸지 않아야 한다.


## 목표

0.1.1은 0.1.0 foundation packages의 품질 증거를 보완하는 patch milestone이다. 이 milestone은 세 가지 결과를 완료 상태로 정의한다.

1. 0.1.0의 설계/범위/비목표가 repo 문서에 남는다.
2. 0.1.0 코드 표면이 Step 6-R 7-tier review를 통과하거나, 발견된 P0/P1이 수정 또는 추적된다.
3. 이후 milestone 작업에서 issue/PR metadata 누락이 반복되지 않도록 생성 직후 검증 gate가 명시된다.

## Acceptance Criteria

- `docs/superpowers/research/2026-06-03-milestone-0.1.1-quality-closure-inventory.md`가 0.1.0 PR과 package surface를 연결한다.
- `docs/superpowers/plans/2026-06-03-milestone-0.1.1-quality-closure-plan.md`가 Step DoD와 validation commands를 정의한다.
- `docs/superpowers/reviews/2026-06-03-milestone-0.1.1-foundation-7tier-review.md`가 Tier 1-7 결과와 P0/P1 상태를 기록한다.
- `docs/lessons/2026-06-03-milestone-0.1.0-workflow-closure.md`가 누락 원인과 재발 방지 규칙을 기록한다.
- P1 JSON trailing-data finding은 `serialization` regression test와 함께 수정된다.
- PR 생성 후 `milestone=0.1.1`, `assignee=debop`을 `gh pr view`로 검증한다.

## Non-goals

- 0.1.0 package API를 재설계하지 않는다.
- `resilience` 0.2.0 surface를 이 review 범위에 포함하지 않는다.
- Testcontainers fixture API를 이번 PR에서 확장하지 않는다.
- GitHub Actions나 릴리스 workflow를 변경하지 않는다.

## 품질 기준

- P0/P1 findings: 0이어야 한다.
- P2 findings: residual risk로 문서화 가능하되, 실제 사용자/CI 차단 위험이면 follow-up issue로 승격한다.
- Validation: targeted package tests, full `go test ./...`, `go vet ./...`, raw `golangci-lint run ./...`, `git diff --check`.
