## Findings

### P1 - Fixed

`serialization.JSONSerializer.Unmarshal` used `decoder.More()` to detect trailing data. `More()` is for arrays/objects and does not reliably reject a second top-level JSON value after the first decode. That allowed a payload such as `{"id":"acct-1","active":true}{"id":"acct-2","active":false}` to decode the first value and ignore the second.

Resolution:

- Issue: `#94`
- Fix: `serialization/json.go` now performs a second decode and requires `io.EOF`.
- Regression: `serialization/serialization_test.go` adds `TestJSONSerializerRejectsTrailingJSONValue`.
- Targeted test: `go test -count=1 ./serialization` passed with 13 tests.

### P2 - Residual Risk

Testcontainers fixtures terminate containers with `context.Background()` in `t.Cleanup`. If Docker/container termination hangs, cleanup can stall the test process. This is not a confirmed failing behavior in the current run, but a bounded cleanup context would be safer for CI reliability.

Affected files:

- `testcontainers/redis/redis.go`
- `testcontainers/postgres/postgres.go`
- `testcontainers/mysql/mysql.go`
- `testcontainers/kafka/kafka.go`
- `testcontainers/nats/nats.go`

Disposition: record as residual P2. It does not block 0.1.1 because no current failure was reproduced and the change would touch all fixture packages.
