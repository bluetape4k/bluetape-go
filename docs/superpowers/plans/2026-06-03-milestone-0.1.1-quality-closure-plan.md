# Milestone 0.1.1 Quality Closure Plan

## 분류

- 작업 유형: Type E - Maintenance.
- 근거: release quality closure, validation evidence, documentation alignment를 다룬다.
- 범위: `0.1.1` milestone에 남은 품질·문서·검증 항목을 닫는다.

## 목표

`0.1.1` release 후보가 README, package docs, tests, lint, vet, diff hygiene 측면에서 일관된 상태인지 확인하고, 다음 milestone로 넘길 항목을 명확히 분리한다.

## 순서

1. milestone issue 목록과 PR 상태를 확인한다.
2. 완료된 기능의 README/README.ko.md, package docs, examples 정합성을 확인한다.
3. release note와 CHANGELOG 항목이 실제 변경 범위와 맞는지 점검한다.
4. flaky 또는 infrastructure-dependent test를 별도 risk로 기록한다.
5. `make fmt-check`, `make tidy-check`, `make vet`, `make lint`, `make test`, `git diff --check`를 실행한다.
6. 실패가 있으면 원인별로 issue 또는 follow-up PR을 만든다.
7. release-ready evidence를 한 곳에 정리한다.

## 리뷰 게이트

- release scope와 milestone scope가 일치하는지 확인한다.
- README locale pair가 public behavior를 같은 수준으로 설명하는지 확인한다.
- 테스트 실패가 코드 결함인지 infrastructure failure인지 구분한다.
- 다음 milestone로 넘긴 항목이 별도 이슈로 추적되는지 확인한다.

## 검증 게이트

- `make fmt-check`
- `make tidy-check`
- `make vet`
- `make lint`
- `make test`
- `git diff --check`
