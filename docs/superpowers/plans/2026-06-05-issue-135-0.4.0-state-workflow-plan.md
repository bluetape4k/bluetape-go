# Issue 135 0.4.0 State Workflow Plan

## 분류

- 작업 유형: Type A - Full Feature.
- 근거: state/workflow package family, public APIs, examples, documentation, validation artifacts를 포함한다.
- 범위: milestone `0.4.0`의 state와 workflow runner 기반을 정리한다.

## 목표

state abstraction, workflow runner, work report가 서로 독립적으로 테스트 가능하면서도 사용자에게 일관된 workflow story를 제공하도록 milestone 범위를 닫는다.

## 순서

1. #26 state, #27 workflow runners, #28 workreport의 issue scope를 비교한다.
2. shared terminology와 package boundaries를 spec/plan에 반영한다.
3. state transition, runner lifecycle, reporting output의 최소 public API를 고정한다.
4. 각 package에 deterministic tests와 examples를 추가한다.
5. README/README.ko.md와 CHANGELOG/WIP가 milestone 상태를 정확히 설명하도록 갱신한다.
6. repo-wide validation과 review gate를 실행한다.

## 리뷰 게이트

- state package가 workflow runner 세부사항을 모르는지 확인한다.
- workflow runner가 report format에 과도하게 결합하지 않는지 확인한다.
- public API가 context cancellation과 error wrapping을 지키는지 확인한다.
- examples가 실제 caller workflow를 보여주는지 확인한다.
- milestone 문서가 완료/이월 범위를 명확히 구분하는지 확인한다.
