# Issue #399 SerDe Benchmark Fixture and Scenario Matrix

Issue: #399
Parent: #398
Milestone: 0.14.0
Date: 2026-07-07
Work type: Benchmark planning evidence

## Goal

Define the shared payload fixtures and benchmark scenario matrix for the
cross-repo serialization, codec, and compression baseline across
`bluetape-go`, `bluetape-rs`, and JVM bluetape4k modules.

This document is a contract for the benchmark runners that follow in #400 and
for raw evidence preservation in #401. It does not record benchmark results and
does not choose a production default.

## Source Evidence

| Repository | Current surface used for the matrix |
|---|---|
| `bluetape-go` | `serialization` JSON/versioned envelope serializers, `codec` byte/text encoders, and `compression` gzip/zstd/lz4/snappy benchmarks. |
| `bluetape-rs` | `bluetape-rs-codec`, `bluetape-rs-compression`, and `bluetape-rs-serialization` metadata/trait contracts; concrete serialization adapters are follow-up work. |
| `bluetape4k-projects` | JVM `io` serializers, compressors, Jackson/Fastjson/Protobuf/Avro modules, and Redis/Lettuce binary codec combinations such as Fory/Kryo/JDK with lz4/gzip/zstd/snappy. |

## Fixture Rules

- Store fixture definitions as UTF-8 JSON manifest records unless the fixture is
  intentionally binary.
- Generate bytes deterministically from the manifest; do not depend on map
  iteration, wall-clock time, random seeds, locale defaults, or host timezone.
- Use RFC3339 UTC timestamps with nanoseconds omitted unless a scenario is
  explicitly testing timestamp precision.
- Represent high-precision decimal values as strings plus an optional integer
  minor-unit field; do not compare floating-point text across runtimes.
- Treat absent optional fields and explicit `null` as separate compatibility
  cases.
- Keep fixture names stable. Additive fixture revisions use a new `vN` suffix
  instead of mutating the old fixture.
- Record generated byte size next to every raw benchmark output; size drift
  invalidates cross-run comparisons.

| `serde-binary-payload-v1` | Binary payload | 48-256 KiB | Opaque byte payload with magic prefix, one-byte version, deterministic mixed low-entropy regions, and trailing checksum bytes. | This fixture is measured through byte serializers/codecs/compression only. | `serde-repeated-collection-v1` | Repeated collection | 128-768 KiB | Stable list of event records with repeated enums, monotonic sequence numbers, repeated tenant IDs, and deterministic message text. | Preserve item order. ## Scenario Matrix

Metric direction:

- Lower `ns/op` or runtime-specific elapsed time is better.
- Lower allocation count and allocated bytes are better when the runtime exposes
  comparable allocation metrics.
- Lower encoded bytes and lower compressed/original ratio are better for
  density.
- Higher MB/s is better for throughput.
- Invalid-input scenarios are correctness gates first; timing is secondary and
  must not hide accepted malformed input.

Raw output requirement:

- Go: preserve full `go test -run '^$' -bench ... -benchmem` output.
- Rust: preserve full `cargo bench` or Criterion output plus the exact feature
  set.
- JVM: preserve full Gradle/JMH output plus JVM arguments and warmup/measurement
  settings.
- All runtimes: store environment metadata with OS/arch, CPU, runtime version,
  git SHA, dirty-tree status, command, fixture version, generated byte sizes,
  and enabled serializers/compressors.

| Scenario ID | Applies to | Fixtures | Required metrics | Raw output format | Notes |
|---|---|---|---|---|---|
| `encode` | Serialization adapters and byte/text codecs | small, medium, repeated, envelopes; binary for byte serializers/codecs | elapsed time, allocs where available, encoded bytes | Runtime-native benchmark output plus fixture size table | Validate the first encoded value before the timed loop. |
| `decode` | Serialization adapters and byte/text codecs | same as `encode` | elapsed time, allocs where available, decoded object/byte equality | Runtime-native benchmark output plus encoded byte size | Decode from a precomputed encoded value. Validate full equality, not only non-nil output. |
| `roundtrip` | Serialization adapters and byte/text codecs | all applicable fixtures | elapsed time, allocs where available, encoded bytes | Runtime-native benchmark output | Encode then decode in one iteration. Use this for caller-visible end-to-end cost, not as a substitute for separate encode/decode rows. |
| `serialize_then_compress` | Serialization plus compression | small, medium, repeated, envelopes | elapsed time, allocs, serialized bytes, compressed bytes, ratio | Runtime-native benchmark output plus compressor list | Canonical path for object payloads: serialize object bytes, then compress. |
| `compress_then_serialize` | Byte payload wrappers only | binary payload and explicitly byte-oriented envelopes | elapsed time, allocs, compressed bytes, final envelope bytes | Runtime-native benchmark output | Not valid for ordinary object serializers unless the serializer contract explicitly accepts already-compressed bytes. |
| `decompress_then_decode` | Compression plus serialization | precompressed serialized fixtures | elapsed time, allocs, decoded equality | Runtime-native benchmark output | Setup must validate compressed bytes can be decompressed and decoded before timer reset. |
| `invalid_truncated_input` | Decoders and decompressors | truncated encoded bytes for every applicable fixture | accepted/rejected result, error type/category, elapsed time only after correctness passes | Runtime-native test/benchmark output with error category table | Must fail closed. Do not compare speed for a decoder that accepts malformed input. |
| `unknown_field_or_version` | Structured serializers/envelopes | small object, medium object, envelope v1/v2 | accepted/rejected result, error type/category, elapsed time only after correctness passes | Runtime-native test/benchmark output with policy table | Record strict vs ignore-unknown behavior; they are different policies, not winners/losers by themselves. |

## Runtime Mapping

| Runtime | Serialization candidates | Codec candidates | Compression candidates |
|---|---|---|---|
| Go | `serialization.JSONSerializer`, `serialization.BytesSerializer`, `serialization.StringSerializer`, `serialization.VersionedSerializer` | `codec` Base64/Base64URL/Hex/Base58/Base62/URL62 where the scenario is byte/text encoding | `compression.All()` currently gzip, zstd, lz4, snappy |
| Rust | `bluetape-rs-serialization` metadata/trait contract; concrete adapters only after their owning issue lands | `bluetape-rs-codec` hex/Base64/Base58/Base62/text helpers | `bluetape-rs-compression` algorithms enabled by feature set |
| JVM | Jackson/Fastjson/Protobuf/Avro/Fory/Kryo/JDK candidates only where the module owns a safe adapter and trust boundary | JVM codec helpers and Redis codec wrappers when they encode comparable byte/text values | `io` compressors and Redis/Lettuce codec combinations using gzip/lz4/zstd/snappy |

## Compatibility Notes

- Field naming: manifests use snake_case. Runners must record whether the
  runtime emits snake_case, camelCase, field numbers, or class metadata.
- Numeric precision: decimal values must not be coerced through binary floating
  point. Use decimal text and minor units for equality checks.
- Time values: timestamps are UTC RFC3339 strings unless the runner documents a
  native timestamp format. Local timezone defaults are excluded.
- Optional fields: absent and explicit `null` are separate fixtures.
- Binary payloads: do not base64-wrap binary payloads inside object serializers
  unless the scenario records that extra codec layer.
- Trust boundary: JVM Fory/Kryo/JDK fallback codecs are trusted-internal
  candidates. Cross-repo recommendations must not promote them for untrusted
  input without a separate security review.
- Wire compatibility: Fory, FastFory, Kryo, JDK, Protobuf, JSON, and versioned
  envelopes are separate wire formats. Benchmark comparison may compare cost,
  but it must not imply interoperability unless round-trip compatibility is
  explicitly tested in both directions.

## Exclusions

- No production ranking from one local benchmark window.
- No new serializer or compressor adapter only to make another runtime's matrix
  symmetric.
- No public API churn before #400/#401 produce raw evidence.
- No hidden lossy field conversion, timestamp localization, or float coercion.
- No comparison between strict and lenient decoders without labeling the policy
  difference.
- No compressed-size-only recommendation; encode/decode/decompress cost and
  correctness gates remain part of the decision.
