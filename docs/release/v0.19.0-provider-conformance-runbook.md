# v0.19.0 Provider Conformance Rollout Runbook

This runbook is the release gate for the v0.19.0 single-leader, Redis lock, and
Redis rate-limit contract changes. Service owners may tighten these gates, but
must not relax them.

## English

### Before The Canary

- Inventory every caller-owned campaign deadline and every `Group`, `MemberID`,
  `KeyPrefix`, and custom Redis lock token. Remove identities rejected by the
  new structural validation before deploying a new binary.
- Mixed old/new binaries retain generated leader/lock tokens, Redis keys, TTLs,
  and storage formats. The exception is a custom lock token with leading or
  trailing whitespace: v0.19.0 preserves those bytes while older binaries may
  have trimmed them. Do not mix versions for that owner until its token identity
  is migrated.
- Expect an old single Redis leader contender to return `ErrNotLeader`
  immediately, while v0.19.0 waits until acquisition or its caller deadline.
- For `leader/sql`, apply `sqlleader.SchemaSQL` with a migration owner before
  the canary. Verify the exact seven-column catalog, primary key, no hostile
  triggers/RLS, and a runtime role limited to schema usage plus table DML.
  Every endpoint and reconciliation probe must reach the same writable
  PostgreSQL primary; record server identity and HA timeline, and fence the old
  writer before promotion.

### SQL Rate Limiter Deployment Gates

Execute the following migration gates in this exact order and retain their
outputs in the deployment record.

1. First, verify public schema ownership is the approved migration owner:

   ```sql
   select pg_catalog.pg_get_userbyid(n.nspowner) as schema_owner
   from pg_catalog.pg_namespace n
   where n.nspname = 'public';
   ```

2. As that owner, remove ambient object creation:

   ```sql
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   ```

3. Verify effective CREATE is false for the runtime role, `PUBLIC`, and every
   inherited role. This check is required even when direct grants look safe:

   ```sql
   set local role app_runtime;
   select current_user,
          has_schema_privilege(current_user, 'public', 'CREATE') as runtime_create,
          has_schema_privilege('PUBLIC', 'public', 'CREATE') as public_create;
   ```

4. Use bounded migration locks and execution time in a transaction:

   ```sql
   begin;
   SET LOCAL lock_timeout = '5s';
   SET LOCAL statement_timeout = '30s';
   -- Execute sqlratelimit.SchemaSQL here as the migration owner.
   commit;
   ```

5. Catalog preflight must return the expected nine columns, types, nullability,
   checks, `(namespace, bucket_key)` primary key, expiry index, owner, no user
   triggers, and disabled row-level security with no policies:

   ```sql
   select a.attname, pg_catalog.format_type(a.atttypid, a.atttypmod) as type,
          a.attnotnull
   from pg_catalog.pg_attribute a
   where a.attrelid = 'public.bluetape_ratelimit_buckets'::regclass
     and a.attnum > 0 and not a.attisdropped
   order by a.attnum;

   select con.contype, pg_catalog.pg_get_constraintdef(con.oid) as definition
   from pg_catalog.pg_constraint con
   where con.conrelid = 'public.bluetape_ratelimit_buckets'::regclass
   order by con.contype, con.conname;

   select i.indexrelid::regclass as index_name, i.indisprimary, i.indisvalid,
          pg_catalog.pg_get_indexdef(i.indexrelid) as definition
   from pg_catalog.pg_index i
   where i.indrelid = 'public.bluetape_ratelimit_buckets'::regclass
   order by index_name::text;

   select c.relkind, pg_catalog.pg_get_userbyid(c.relowner) as owner,
          c.relrowsecurity, c.relforcerowsecurity,
          (select count(*) from pg_catalog.pg_trigger t
           where t.tgrelid = c.oid and not t.tgisinternal) as user_triggers,
          (select count(*) from pg_catalog.pg_policy p
           where p.polrelid = c.oid) as policies
   from pg_catalog.pg_class c
   where c.oid = 'public.bluetape_ratelimit_buckets'::regclass;
   ```

6. Runtime grants come last. The runtime role receives only schema usage and
   table DML, and the verification must show no schema creation or table DDL:

   ```sql
   grant usage on schema public to app_runtime;
   grant select, insert, update, delete
   on table public.bluetape_ratelimit_buckets to app_runtime;

   set local role app_runtime;
   select has_schema_privilege(current_user, 'public', 'USAGE') as schema_usage,
          has_schema_privilege(current_user, 'public', 'CREATE') as schema_create,
          has_table_privilege(current_user,
            'public.bluetape_ratelimit_buckets',
            'SELECT,INSERT,UPDATE,DELETE') as table_dml,
          has_table_privilege(current_user,
            'public.bluetape_ratelimit_buckets',
            'TRUNCATE,REFERENCES,TRIGGER') as table_ddl;
   ```

Route runtime traffic through a primary-only endpoint. Before and after a
controlled failover, retain this writable-primary proof together with the HA
controller's server identity and HA timeline:

```sql
select pg_catalog.inet_server_addr() as server_addr,
       pg_catalog.inet_server_port() as server_port,
       pg_catalog.pg_is_in_recovery() as in_recovery,
       current_setting('transaction_read_only') as read_only,
       pg_catalog.pg_postmaster_start_time() as postmaster_started,
       pg_catalog.pg_current_wal_lsn() as wal_lsn;
```

Promotion requires `pg_is_in_recovery() = false` and
`transaction_read_only = off` at every `Allow`, `Cleanup`, catalog, and probe
endpoint. Reject read replicas and statement/transaction replay proxies.

Run provider tests serially because PostgreSQL Testcontainers share resources:

```bash
go test -count=1 ./ratelimit/sql
go test -race -p1 -count=1 ./ratelimit/sql
```

The caller-owned cleanup scheduler must use a cadence shorter than `IdleTTL`, a
fresh bounded context per invocation, and a `Cleanup` limit in `1..1000`.
Configure database lock and statement timeouts, jitter, and small bounded worker
concurrency. Predeclare the maximum batches and elapsed budget for each run.
Pause cleanup when any predeclared WAL growth, row-lock latency, pool-wait, or
autovacuum pressure gate breaches. On error the returned count is zero although
up to `limit` rows may already be deleted. A retry advances the currently
expired work; it is not an idempotent replay of the previous batch.

Record promotion gates relative to a stable baseline: bounded-cardinality
`Allow` latency/outcome/error categories, `sql.DBStats` wait and in-use values,
statement and row-lock latency, cleanup count/duration/error/backlog and oldest
expiry, live/dead tuples, table/index size, autovacuum lag, and WAL growth. Each
deployment must predeclare a consecutive breach count and a minimum canary
observation window. Do not substitute universal numeric thresholds for a
service-owned baseline and capacity envelope.

Metric labels and logs must not contain key, namespace, DSN, endpoint, or raw
error text. A redacted `KeyID` is allowed only in sampled diagnostics and never
as a metric label.

Local, Redis, and SQL quota state is independent. Use an independent canary namespace
and independent canary cohort. Mixed-provider serving is prohibited
because each provider can grant a full burst. For cutover and rollback, quiesce
the old provider and wait one full-refill window before single-provider
activation, or record an approved extra-burst budget for the overlap.

Before production promotion, a controlled failover must prove old-writer
fencing, durability/RPO, no statement replay, and no replay of commit-unknown
operations. Record the chosen synchronous durability and recovery-point
objective; a pool reconnect test is not HA evidence.

Binary rollback must retain the SQL relation, expiry index, and grants so the
provider can be restored without a schema race. Destructive removal is a
separate destructive migration allowed only after a predeclared observation
window proves zero SQL-provider binary deployment and zero SQL-provider traffic.
Record a pre-removal rollback point, then verify the relation, index, and
privileges are absent only after that migration commits successfully.

### SQL Batch Checkpoint Deployment Gates

Execute these gates in order for `batch/sqlcheckpoint`; retain the catalog,
privilege, primary-identity, drill, and approval evidence with the deployment.

1. Remove ambient `PUBLIC CREATE` as the current schema owner, then transfer
   the schema to the dedicated migration owner. Verify ownership before using
   `SET LOCAL ROLE`; a matching role name is not ownership proof. Both the owner
   and runtime must be `NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION
   NOBYPASSRLS`. The only owner membership edge is the approved deployer with
   `INHERIT FALSE`, `SET TRUE`, and `ADMIN FALSE`; runtime has no inbound or
   outbound membership, and neither owner nor deployer has another edge.

   ```sql
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   GRANT sqlcheckpoint_migration_owner TO app_deployer
     WITH INHERIT FALSE, SET TRUE, ADMIN FALSE;
   ALTER SCHEMA public OWNER TO sqlcheckpoint_migration_owner;

   select pg_catalog.pg_get_userbyid(n.nspowner) as schema_owner
   from pg_catalog.pg_namespace n
   where n.nspname = 'public';
   ```

2. With bounded `lock_timeout`, `statement_timeout`, and
   `idle_in_transaction_session_timeout`, apply `sqlcheckpoint.SchemaSQL` in a
   deployer-owned transaction. Before runtime grants, the catalog preflight
   must prove the exact ordered five columns, fixed size/revision checks,
   `(namespace, checkpoint_key)` primary key, permanent table persistence,
   approved owner, no RLS/policies, no user triggers or rewrite rules, and no
   table or column ACL for the runtime role, `PUBLIC`, or unrelated grantees.
   Keep this transaction open only while reviewing the results below; any
   mismatch requires an immediate `ROLLBACK` and aborts the deployment.

   ```sql
   begin;
   SET LOCAL lock_timeout = '5s';
   SET LOCAL statement_timeout = '30s';
   SET LOCAL idle_in_transaction_session_timeout = '45s';
   SET LOCAL ROLE sqlcheckpoint_migration_owner;
   -- Execute sqlcheckpoint.SchemaSQL here.

   select a.attnum, a.attname,
          pg_catalog.format_type(a.atttypid, a.atttypmod) as type,
          a.attnotnull,
          coalesce(pg_catalog.array_length(a.attacl, 1), 0) as column_acl_count
   from pg_catalog.pg_attribute a
   where a.attrelid = 'public.bluetape_batch_checkpoints'::regclass
     and a.attnum > 0 and not a.attisdropped
   order by a.attnum;

   select con.conname, con.contype, con.convalidated,
          con.condeferrable, con.condeferred,
          pg_catalog.pg_get_constraintdef(con.oid) as definition
   from pg_catalog.pg_constraint con
   where con.conrelid = 'public.bluetape_batch_checkpoints'::regclass
   order by con.contype, con.conname;

   select i.indisvalid, i.indisready, i.indisprimary, i.indisunique,
          i.indnkeyatts, i.indnatts,
          coalesce((select pg_catalog.string_agg(a.attname, ',' order by key.ordinality)
                    from pg_catalog.unnest(i.indkey) with ordinality as key(attnum, ordinality)
                    left join pg_catalog.pg_attribute a
                      on a.attrelid = i.indrelid and a.attnum = key.attnum), '') as columns,
          coalesce(pg_catalog.pg_get_expr(i.indpred, i.indrelid), '') as predicate,
          coalesce(pg_catalog.pg_get_expr(i.indexprs, i.indrelid), '') as expressions
   from pg_catalog.pg_index i
   where i.indrelid = 'public.bluetape_batch_checkpoints'::regclass
     and i.indisprimary;

   select c.relkind, c.relpersistence, c.relrowsecurity, c.relforcerowsecurity,
          owner.rolname as owner, owner.rolcanlogin as owner_login,
          owner.rolsuper, owner.rolcreatedb, owner.rolcreaterole,
          owner.rolreplication, owner.rolbypassrls, c.relacl,
          (select count(*) from pg_catalog.pg_trigger t
           where t.tgrelid = c.oid and not t.tgisinternal) as user_triggers,
          (select count(*) from pg_catalog.pg_policy p
           where p.polrelid = c.oid) as policies,
          (select count(*) from pg_catalog.pg_rewrite r
           where r.ev_class = c.oid and r.rulename <> '_RETURN') as rewrite_rules
   from pg_catalog.pg_class c
   join pg_catalog.pg_roles owner on owner.oid = c.relowner
   where c.oid = 'public.bluetape_batch_checkpoints'::regclass;

   select granted.rolname as granted_role, member.rolname as member_role,
          m.inherit_option, m.set_option, m.admin_option
   from pg_catalog.pg_auth_members m
   join pg_catalog.pg_roles granted on granted.oid = m.roleid
   join pg_catalog.pg_roles member on member.oid = m.member
   where granted.rolname in ('sqlcheckpoint_migration_owner', 'app_deployer', 'app_runtime')
      or member.rolname in ('sqlcheckpoint_migration_owner', 'app_deployer', 'app_runtime')
   order by granted_role, member_role;

   select count(*) as invalid_rows
   from public.bluetape_batch_checkpoints
   where namespace is null or pg_catalog.octet_length(namespace) not between 1 and 128
      or checkpoint_key is null or pg_catalog.octet_length(checkpoint_key) not between 1 and 1024
      or revision is null or revision <= 0
      or payload is null or pg_catalog.octet_length(payload) > 16777216
      or updated_at is null;

   select coalesce(grantee.rolname, 'PUBLIC') as grantee,
          acl.privilege_type, acl.is_grantable
   from pg_catalog.pg_class c
   cross join lateral pg_catalog.aclexplode(
     coalesce(c.relacl, pg_catalog.acldefault('r', c.relowner))) acl
   left join pg_catalog.pg_roles grantee on grantee.oid = acl.grantee
   where c.oid = 'public.bluetape_batch_checkpoints'::regclass
   order by grantee, acl.privilege_type;
   ```

   The preflight passes only when all of these results match exactly:

   - columns `namespace bytea`, `checkpoint_key bytea`, `revision bigint`,
     `payload bytea`, and `updated_at timestamp with time zone`, in that order,
     all `NOT NULL`, with `column_acl_count = 0`;
   - exactly `bluetape_batch_checkpoints_pkey` over
     `(namespace, checkpoint_key)`, plus
     `bluetape_batch_checkpoints_namespace_size_check` for `1..128` bytes,
     `bluetape_batch_checkpoints_key_size_check` for `1..1024` bytes,
     `bluetape_batch_checkpoints_revision_check` for `revision > 0`, and
     `bluetape_batch_checkpoints_payload_size_check` for at most 16 MiB; all
     five constraints are validated, non-deferrable, and initially immediate;
   - one valid, ready, primary, unique two-key index over exactly
     `namespace,checkpoint_key`, with no predicate or expression;
   - `relkind = 'r'`, `relpersistence = 'p'`, owner
     `sqlcheckpoint_migration_owner` with `owner_login = false` and all five
     privileged attributes false, RLS flags false, and
     policy/trigger/rewrite-rule/invalid-row counts all zero;
   - the membership query returns exactly owner-to-approved-deployer with
     `inherit_option = false`, `set_option = true`, and `admin_option = false`;
     it returns no runtime edge and no other owner or deployer edge;
   - table ACL entries for the non-login owner only. Any other row requires
     `ROLLBACK`; do not continue to runtime grants.

3. In the same session and transaction, apply runtime grants only after catalog
   preflight succeeds. The runtime role
   must be `LOGIN NOINHERIT`, have no inbound or outbound role memberships,
   have `rolsuper`, `rolcreatedb`, `rolcreaterole`, `rolreplication`, and
   `rolbypassrls` all false, and receive exactly
   schema `USAGE` plus table `SELECT`, `INSERT`, and `UPDATE`, without grant
   options. Reject `DELETE`, `TRUNCATE`, `REFERENCES`, `TRIGGER`, schema
   `CREATE`, any column ACL, and table grants to `PUBLIC` or unrelated roles.
   PostgreSQL's default non-grantable `PUBLIC USAGE` on schema `public` is
   allowed; `PUBLIC CREATE` is not. The complete schema ACL allowlist is owner
   `USAGE/CREATE`, non-grantable `PUBLIC USAGE`, and non-grantable runtime
   `USAGE`. No other schema ACL entry is accepted.

   ```sql
   grant usage on schema public to app_runtime;
   grant select, insert, update
   on table public.bluetape_batch_checkpoints to app_runtime;

   select coalesce(grantee.rolname, 'PUBLIC') as grantee,
          acl.privilege_type, acl.is_grantable
   from pg_catalog.pg_namespace n
   cross join lateral pg_catalog.aclexplode(
     coalesce(n.nspacl, pg_catalog.acldefault('n', n.nspowner))) acl
   left join pg_catalog.pg_roles grantee on grantee.oid = acl.grantee
   where n.nspname = 'public'
   order by 1, 2;

   select r.rolcanlogin, r.rolinherit, r.rolsuper, r.rolcreatedb,
          r.rolcreaterole, r.rolreplication, r.rolbypassrls,
          (select count(*) from pg_catalog.pg_auth_members m
           where m.member = r.oid) as outbound_memberships,
          (select count(*) from pg_catalog.pg_auth_members m
           where m.roleid = r.oid) as inbound_memberships
   from pg_catalog.pg_roles r where r.rolname = 'app_runtime';

   select a.attname, a.attacl
   from pg_catalog.pg_attribute a
   where a.attrelid = 'public.bluetape_batch_checkpoints'::regclass
     and a.attnum > 0 and not a.attisdropped and a.attacl is not null;

   set local role app_runtime;
   select current_user,
          has_schema_privilege(current_user, 'public', 'USAGE') as schema_usage,
          has_schema_privilege(current_user, 'public', 'CREATE') as schema_create,
          has_schema_privilege(current_user, 'public',
            'USAGE WITH GRANT OPTION') as schema_usage_grant_option,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'SELECT') as can_select,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints',
            'SELECT WITH GRANT OPTION') as select_grant_option,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'INSERT') as can_insert,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints',
            'INSERT WITH GRANT OPTION') as insert_grant_option,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'UPDATE') as can_update,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints',
            'UPDATE WITH GRANT OPTION') as update_grant_option,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'DELETE') as can_delete,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'TRUNCATE') as can_truncate,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'REFERENCES') as can_references,
          has_table_privilege(current_user,
            'public.bluetape_batch_checkpoints', 'TRIGGER') as can_trigger;

   reset role;
   COMMIT;
   ```

   Commit only when `app_runtime` is `LOGIN NOINHERIT` with zero memberships;
   the column-ACL query returns zero rows; schema usage and table
   select/insert/update are true; every create/delete/truncate/references/trigger
   and grant-option result is false; and the schema ACL rows match the allowlist
   above. On any query error or unexpected value, run `ROLLBACK` instead and stop
   the deployment. Store the successful result set and commit outcome.

4. Route the runtime pool and every reconciliation probe to the same writable
   primary with connection-level transaction affinity. Record server identity,
   HA timeline, synchronous durability, and the service RPO. Reject replicas,
   multi-primary routing, statement/transaction replay, and transaction-pooling
   proxies that can move statements between sessions. A reconnect test alone
   does not prove fencing or RPO.

5. Run a production-shaped recovery drill before promotion. The drill must
   prove: successful callback and consumed-input checkpoint commit together;
   a representative callback failure rolls both back; conflict/exhaustion does
   not leak business output; provider-Commit unknown performs one fresh bounded
   `Load` without automatic callback replay; and `ErrAtomicityUnknown` stops
   intake and quiesces the checkpoint key. For atomicity unknown, compare the
   business record and checkpoint on the primary, obtain operator approval for
   a safe idempotent replay or an explicit repair, verify the repaired state,
   and only then release quiesce. Never infer safe replay from the checkpoint
   alone.

   ```bash
   go test -count=1 ./batch ./batch/sqlcheckpoint
   go test -count=20 ./batch/sqlcheckpoint -run 'Concurrent|Conflict|Cancellation|Ownership'
   go test -race -p1 -count=1 ./batch ./batch/sqlcheckpoint
   ```

6. Predeclare low-cardinality telemetry for `load` and `commit` outcomes;
   conflict, exhaustion, commit-unknown, and atomicity-unknown counts;
   cancellation and operation latency; and `sql.DBStats` wait, in-use, idle,
   and lifetime counters. Also gate on row-lock/statement latency, live/dead
   tuples, table size, autovacuum lag, WAL growth, and replication lag. Labels
   may contain only bounded operation, outcome, and sentinel categories. Raw
   namespace, checkpoint key, `KeyID`, DSN, endpoint, payload, SQL, and rendered
   errors must never be a metric label.

7. Start the canary with an isolated namespace/key and business cohort after
   fencing the legacy writer. Predeclare observation windows and consecutive
   breach thresholds for autovacuum lag, replication lag, dead-tuple ratio,
   pool wait, latency, and unknown outcomes. Promotion requires the recovery
   drill and HA/RPO evidence plus zero unresolved unknown outcome. Shutdown is:
   stop intake, cancel and join runs, reconcile unknown outcomes, confirm
   transaction drain, then close the caller-owned pool. Rollback uses the same
   quiesce and reconciliation gate before restoring the legacy checkpoint.
   Retain the SQL table, grants, and both old/new checkpoint evidence through
   the rollback window; delete a row only in an approved maintenance window
   after every run and reconciliation for that key is joined.

### etcd Leader Deployment Gates

Use a TLS-verified, authenticated `etcdctl` profile. The following preflight
must report the expected member/leader and complete a linearizable roundtrip
before any campaign starts:

```bash
export ETCDCTL_API=3
etcdctl --endpoints="$ETCD_ENDPOINTS" endpoint status --write-out=table
etcdctl --endpoints="$ETCD_ENDPOINTS" put "$ETCD_PREFLIGHT_KEY" ready
etcdctl --endpoints="$ETCD_ENDPOINTS" get "$ETCD_PREFLIGHT_KEY"
etcdctl --endpoints="$ETCD_ENDPOINTS" del "$ETCD_PREFLIGHT_KEY"
```

Grant each runtime principal read/write permission only for its encoded exact
range `[ETCD_CANDIDATE_ROOT, rangeEnd)`. Record the tested server version and a
cross-principal attached-lease revoke denial. Principals sharing one range are
mutually trusted; use separate clusters when this lease authorization contract
cannot be proved.

Shutdown and cutover require a campaign drain, stopped and joined protected
work, and bounded same-elector `Resign` while the caller client remains healthy.
If official cleanup stays blocked on `client.Ctx()`, coordinate every shared
client user, close that caller-owned client, join the call, and persist the
unresolved generation. A separate healthy diagnostic client must then prove
the exact range empty:

```bash
test "$ETCD_ACTIVE_CAMPAIGNS" -eq 0
test "$ETCD_PROTECTED_WORKERS" -eq 0
ETCD_EXACT_RANGE_COUNT="$(etcdctl --endpoints="$ETCD_DIAGNOSTIC_ENDPOINTS" get "$ETCD_CANDIDATE_ROOT" --prefix --count-only)"
test "$ETCD_EXACT_RANGE_COUNT" -eq 0
```

Cutover starts etcd contenders only after that proof. A symmetric rollback
stops protected work and every etcd contender, repeats the same exact range
proof, restores the previous provider, and verifies zero etcd contenders.
Provider overlap requires an external fencing authority.

For quorum recovery, never campaign from a minority. Restore a majority,
repeat endpoint Status and the linearizable roundtrip, reconcile every retained
generation, and only then reopen the restart gate. Use an explicit sampling cadence
of `min(RenewInterval, 1s)` for `IsLeader`; alert on the first true-to-false
transition and inventory `ErrCommitUnknown`/`ErrCleanupPending` without raw
endpoint, key, lease, token, or rendered-error labels.

Dependency rollback is a reviewed source change, not a runtime toggle:

```bash
git diff -- go.mod go.sum
git rm -r leader/etcd
# Remove only etcd registrations/claims from these shared files:
# README.md README.ko.md leader/README.md leader/README.ko.md CHANGELOG.md
test -z "$(git grep -n 'leader/etcd' -- README.md README.ko.md leader/README.md leader/README.ko.md CHANGELOG.md)"
go mod tidy
make ci
```

Remove only the provider registration and implementation introduced by this
release; preserve unrelated `leader` and module work. Do not run destructive
rollback while any binary still campaigns through etcd.

### Telemetry And Promotion

Observe campaign wait duration, acquisition, timeout/cancellation, validation
failure, provider failure, `ErrCampaignInProgress`, `ErrCleanupPending`, cleanup
duration, resign retry, TTL fallback, and takeover latency. Separate confirmed,
bare-context, and commit-unknown outcomes. Labels may contain only bounded
backend, operation, outcome, and sentinel categories; never put identity,
endpoint, token, or rendered errors in labels or logs.

Run the canary for at least `max(15 minutes, 10 * maximum leader TTL)` and cover
contention, renewal, resign, and takeover. Promote only when:

- new validation failures and unresolved cleanup-pending records are both zero;
- provider/resign failure and campaign-timeout rates remain within both 20%
  relative and 1 percentage point absolute of the previous stable window;
- campaign-wait and takeover-latency p95 remain at or below 1.2 times baseline;
- every non-etcd cleanup completes by bounded retry or TTL fallback within two
  TTLs; etcd requires successful revoke or a linearizable exact-key/range
  absence proof, and TTL only schedules another proof attempt;
- PostgreSQL pool wait/statement p99 remains inside the
  `Lease-RenewInterval` margin, starvation clears local leadership before
  server-time expiry, and a controlled HA fencing/takeover exercise succeeds.

Hold promotion for any gate breach, raw identifier/error exposure,
goroutine/container leak, cleanup pending beyond two TTLs, or a lease blocking a
new owner. Roll back after a safety/redaction breach or failure to recover across
two consecutive five-minute windows.

### Rollback Completion

Before binary rollback, cancel outstanding campaigns with the service shutdown
context and attempt bounded owner-aware resign. Rollback is complete only after
campaign goroutines are zero, renew traffic is zero, every cleanup is complete,
and a takeover probe succeeds. A recorded remaining TTL is sufficient only for
providers whose contract treats TTL expiry as cleanup; etcd rollback still
requires successful revoke or a linearizable exact-key/range absence proof.
For etcd, TTL only schedules another proof attempt and never completes the gate.
Existing-provider storage formats are unchanged, so they require no data
migration rollback. For `leader/sql`, retain
`public.bluetape_leader_leases` and its grants during binary rollback; table
drop or rewrite requires a later, separately reviewed migration after no
deployed binary uses it.

## 한국어

### Canary 전 점검

- 모든 caller-owned campaign deadline과 `Group`, `MemberID`, `KeyPrefix`, custom
  Redis lock token을 inventory합니다. 새 structural validation이 거부하는 identity는
  새 binary를 배포하기 전에 제거합니다.
- Old/new binary는 generated leader/lock token, Redis key, TTL, storage format을
  그대로 공유합니다. 단, 앞뒤 공백이 있는 custom lock token은 예외입니다. v0.19.0은
  그 byte를 보존하지만 이전 binary는 trim했을 수 있으므로 token identity migration이
  끝날 때까지 해당 owner에서 mixed-version 배포를 하지 않습니다.
- 이전 Redis single leader contender는 즉시 `ErrNotLeader`를 반환하지만 v0.19.0은
  acquire 또는 caller deadline까지 기다립니다.
- `leader/sql`은 canary 전에 migration owner로 `sqlleader.SchemaSQL`을 적용합니다.
  정확한 7개 column catalog, primary key, hostile trigger/RLS 부재, schema usage와 table
  DML만 가진 runtime role을 검증합니다. 모든 endpoint와 reconciliation probe가 같은
  writable PostgreSQL primary에 도달해야 하며 server identity와 HA timeline을 기록하고
  promote 전에 old writer를 fence합니다.

### SQL Rate Limiter 배포 Gate

아래 migration gate는 반드시 순서대로 실행하고 결과를 deployment record에 보관합니다.

1. 먼저 `public` schema owner가 승인된 migration owner인지 조회합니다.

   ```sql
   select pg_catalog.pg_get_userbyid(n.nspowner) as schema_owner
   from pg_catalog.pg_namespace n
   where n.nspname = 'public';
   ```

2. Schema owner로 ambient object 생성 권한을 제거합니다.

   ```sql
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   ```

3. Runtime role, `PUBLIC`, 상속받은 모든 role의 effective `CREATE`가 false인지
   확인합니다. Direct grant가 없어도 이 검증을 생략하지 않습니다.

   ```sql
   set local role app_runtime;
   select current_user,
          has_schema_privilege(current_user, 'public', 'CREATE') as runtime_create,
          has_schema_privilege('PUBLIC', 'public', 'CREATE') as public_create;
   ```

4. Transaction 안에서 migration lock과 실행 시간을 제한합니다.

   ```sql
   begin;
   SET LOCAL lock_timeout = '5s';
   SET LOCAL statement_timeout = '30s';
   -- Migration owner로 sqlratelimit.SchemaSQL을 실행합니다.
   commit;
   ```

5. Catalog preflight에서 9개 column의 name/type/nullability, check constraint,
   `(namespace, bucket_key)` primary key, expiry index, owner를 확인합니다. User trigger가
   없고 row-level security가 비활성화됐으며 policy가 없어야 합니다. 위 English 절의
   catalog query 전체를 실행하고 결과를 보관합니다.

6. Runtime grant는 마지막에 적용합니다. Runtime role에는 schema usage와 table DML만
   부여합니다. Schema creation과 table DDL 권한이 없다는 검증 결과도 보관합니다.

   ```sql
   grant usage on schema public to app_runtime;
   grant select, insert, update, delete
   on table public.bluetape_ratelimit_buckets to app_runtime;
   ```

Runtime traffic은 primary-only endpoint로 보냅니다. Controlled failover 전후로 위
English 절의 writable-primary query와 HA controller의 server identity, HA timeline을
보관합니다. 모든 `Allow`, `Cleanup`, catalog, probe endpoint에서
`pg_is_in_recovery() = false`, `transaction_read_only = off`여야 합니다. Read replica와
statement/transaction replay proxy는 사용하지 않습니다.

PostgreSQL Testcontainer가 resource를 공유하므로 provider test를 직렬로 실행합니다.

```bash
go test -count=1 ./ratelimit/sql
go test -race -p1 -count=1 ./ratelimit/sql
```

Caller-owned cleanup scheduler는 `IdleTTL`보다 짧은 cadence, 매 호출마다 새 bounded
context, `1..1000` 범위의 `Cleanup` limit을 사용합니다. Database lock/statement
timeout, jitter, 작은 bounded worker concurrency를 설정하고 실행별 maximum batch 수와
elapsed budget을 사전에 정합니다. WAL growth, row-lock latency, pool wait, autovacuum
pressure gate 중 하나라도 넘으면 cleanup을 중지합니다. Error가 있으면 반환 count는
0이지만 최대 `limit` row가 이미 삭제됐을 수 있습니다. Retry는 현재 expired work를
진행하며 이전 batch를 idempotent하게 replay한다고 간주하지 않습니다.

Promotion gate는 stable baseline 대비로 기록합니다. Bounded-cardinality `Allow`
latency/outcome/error category, `sql.DBStats` wait/in-use, statement/row-lock latency,
cleanup count/duration/error/backlog/oldest expiry, live/dead tuple, table/index size,
autovacuum lag, WAL growth를 관측합니다. Deployment마다 consecutive breach count와
minimum canary observation window를 사전 선언합니다. 모든 service에 적용할 보편적인
숫자 threshold를 임의로 만들지 않습니다.

Metric label과 log에 key, namespace, DSN, endpoint, raw error를 넣지 않습니다. Redacted
`KeyID`는 sampled diagnostic에서만 허용하고 metric label로 사용하지 않습니다.

Local, Redis, SQL quota state는 독립적입니다. Canary에는 independent namespace와
independent cohort를 사용합니다. Provider마다 full burst를 허용하므로 mixed-provider
serving은 금지합니다. Cutover와 rollback에서는 old provider를 quiesce하고 한 번의
full-refill window를 기다린 뒤 단일 provider를 활성화합니다. 겹치는 구간이 필요하면
approved extra-burst budget을 기록합니다.

Production promotion 전에 controlled failover로 old-writer fencing, durability/RPO,
statement replay 부재, commit-unknown operation 미재실행을 입증합니다. 선택한 synchronous
durability와 recovery-point objective를 기록합니다. Pool reconnect test만으로는 HA를
입증할 수 없습니다.

Binary rollback에서는 SQL relation, expiry index, grant를 유지하여 schema race 없이
provider를 복구할 수 있어야 합니다. Destructive removal은 별도 migration으로 수행합니다.
사전에 정한 observation window 동안 SQL-provider binary deployment와 SQL-provider traffic이
모두 0임을 입증한 뒤에만 허용합니다. 제거 전 rollback point를 기록하고 migration이
commit된 다음 relation, index, privilege가 실제로 사라졌는지 검증합니다.

### SQL Batch Checkpoint 배포 Gate

`batch/sqlcheckpoint`는 아래 gate를 순서대로 실행합니다. Catalog, privilege,
primary identity, drill, approval 증거를 deployment record에 보관합니다.

1. 현재 schema owner 권한으로 `PUBLIC CREATE`를 제거한 뒤 전용 migration owner에게 schema
   ownership을 이전합니다. `SET LOCAL ROLE` 전에 실제 owner를 조회해야 합니다. Role name이
   같다는 사실만으로 ownership을 증명할 수 없습니다. Owner와 runtime은
   `NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS`여야 합니다. Owner에는
   승인된 deployer의 `INHERIT FALSE`, `SET TRUE`, `ADMIN FALSE` membership 하나만 허용하고,
   runtime에는 inbound/outbound membership을 모두 금지하며 owner와 deployer에도 다른
   membership edge가 없어야 합니다.

   ```sql
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   GRANT sqlcheckpoint_migration_owner TO app_deployer
     WITH INHERIT FALSE, SET TRUE, ADMIN FALSE;
   ALTER SCHEMA public OWNER TO sqlcheckpoint_migration_owner;

   select pg_catalog.pg_get_userbyid(n.nspowner) as schema_owner
   from pg_catalog.pg_namespace n
   where n.nspname = 'public';
   ```

2. `lock_timeout`, `statement_timeout`, `idle_in_transaction_session_timeout`이
   제한된 deployer-owned transaction에서 `sqlcheckpoint.SchemaSQL`을 적용합니다. Runtime
   grant 전 catalog preflight로 순서까지 정확한 5개 column, 고정 size/revision check,
   `(namespace, checkpoint_key)` primary key, permanent table, 승인된 owner를 확인합니다.
   RLS/policy, user trigger, rewrite rule이 없어야 하며 runtime role, `PUBLIC`, 무관한
   grantee에 table ACL이나 column ACL이 없어야 합니다. 위 English 절의 catalog query를
   그대로 실행해 결과를 보관합니다. 기대 결과와 하나라도 다르면 즉시 `ROLLBACK`하고
   배포를 중단합니다. 정확한 5개 column, 5개 constraint, 2-column primary index,
   non-login owner, permanent ordinary table, 0개 hostile object/invalid row, owner-only table
   ACL, owner/runtime의 고권한 role attribute 부재, 승인된 deployer membership만 존재함을
   모두 확인한 뒤에만 다음 단계로 진행합니다.

3. 같은 session과 transaction에서 catalog preflight가 성공한 뒤에만 runtime grant를
   적용합니다. Runtime role은
   `LOGIN NOINHERIT`이고 inbound/outbound role membership이 없어야 하며 `rolsuper`,
   `rolcreatedb`, `rolcreaterole`, `rolreplication`, `rolbypassrls`가 모두 false여야 합니다.
   Schema `USAGE`와 table
   `SELECT`, `INSERT`, `UPDATE`만 grant option 없이 부여합니다. `DELETE`, `TRUNCATE`,
   `REFERENCES`, `TRIGGER`, schema `CREATE`, 모든 column ACL, `PUBLIC` 또는 무관한 role의
   table grant는 거부합니다. Schema `public`의 기본 `PUBLIC USAGE`는 grant option이 없는
   경우에만 허용하고 `PUBLIC CREATE`는 금지합니다. 허용하는 schema ACL은 owner의
   `USAGE/CREATE`, grant option 없는 `PUBLIC USAGE`, grant option 없는 runtime `USAGE`뿐입니다.
   위 English 절의 schema ACL allowlist, role membership, column ACL, effective privilege와
   grant-option query도 실행하고 결과를 보관합니다.

   ```sql
   grant usage on schema public to app_runtime;
   grant select, insert, update
   on table public.bluetape_batch_checkpoints to app_runtime;
   -- English 절의 모든 검증 결과가 정확히 일치할 때만 실행합니다.
   reset role;
   COMMIT;
   ```

   결과가 하나라도 다르거나 query가 실패하면 `COMMIT`하지 말고 `ROLLBACK`한 뒤 배포를
   중단합니다. 성공한 result set과 commit 결과를 deployment record에 보관합니다.

4. Runtime pool과 모든 reconciliation probe는 connection-level transaction affinity를
   유지하며 같은 writable primary에 연결해야 합니다. Server identity, HA timeline,
   synchronous durability, service RPO를 기록합니다. Read replica, multi-primary routing,
   statement/transaction replay, session 사이에서 statement를 옮기는 transaction-pooling
   proxy는 거부합니다. Reconnect test만으로 fencing이나 RPO를 증명할 수 없습니다.

5. Promotion 전에 production 형태의 recovery drill을 실행합니다. 성공 시 callback과
   consumed-input checkpoint가 함께 commit되는지, 대표 callback failure에서 둘 다
   rollback되는지, conflict/exhaustion이 business output을 남기지 않는지 확인합니다.
   Provider-Commit unknown은 callback을 자동 replay하지 않고 새 bounded `Load`를 한 번만
   수행해야 합니다. `ErrAtomicityUnknown`이면 intake를 멈추고 checkpoint key를 quiesce한
   뒤 primary에서 business record와 checkpoint를 대조합니다. 안전한 idempotent replay나
   명시적 repair는 operator approval을 받은 뒤 실행하고, repaired state를 검증한 다음에만
   quiesce를 해제합니다. Checkpoint만 보고 replay가 안전하다고 판단하면 안 됩니다.

   ```bash
   go test -count=1 ./batch ./batch/sqlcheckpoint
   go test -count=20 ./batch/sqlcheckpoint -run 'Concurrent|Conflict|Cancellation|Ownership'
   go test -race -p1 -count=1 ./batch ./batch/sqlcheckpoint
   ```

6. `load`와 `commit` outcome, conflict, exhaustion, commit-unknown,
   atomicity-unknown count, cancellation, operation latency를 low-cardinality telemetry로
   사전 정의합니다. `sql.DBStats`의 wait/in-use/idle/lifetime counter와 row-lock/statement
   latency, live/dead tuple, table size, autovacuum lag, WAL growth, replication lag도 gate로
   사용합니다. Label에는 bounded operation, outcome, sentinel category만 넣습니다. Raw
   namespace, checkpoint key, `KeyID`, DSN, endpoint, payload, SQL, rendered error는 metric
   label로 사용하면 안 됩니다.

7. Legacy writer를 fence한 뒤 isolated namespace/key와 business cohort로 canary를
   시작합니다. Autovacuum lag, replication lag, dead-tuple ratio, pool wait, latency,
   unknown outcome의 observation window와 consecutive breach threshold를 사전 선언합니다.
   Recovery drill, HA/RPO 증거, unresolved unknown outcome 0건을 모두 만족해야 promote할 수
   있습니다. Shutdown은 intake stop, run cancel/join, unknown outcome reconciliation,
   transaction drain 확인, caller-owned pool close 순서입니다. Rollback도 legacy checkpoint를
   복원하기 전에 같은 quiesce/reconciliation gate를 거칩니다. Rollback window 동안 SQL
   table, grant, old/new checkpoint 증거를 보존합니다. 모든 실행과 해당 key의 조정 작업이
   종료된 뒤 승인된 유지보수 시간에만 row를 삭제합니다.

### etcd Leader Deployment Gates

TLS hostname 검증과 인증을 적용한 `etcdctl` profile을 사용합니다. Campaign을 시작하기
전에 다음 preflight로 예상 member/leader와 linearizable roundtrip을 확인합니다.

```bash
export ETCDCTL_API=3
etcdctl --endpoints="$ETCD_ENDPOINTS" endpoint status --write-out=table
etcdctl --endpoints="$ETCD_ENDPOINTS" put "$ETCD_PREFLIGHT_KEY" ready
etcdctl --endpoints="$ETCD_ENDPOINTS" get "$ETCD_PREFLIGHT_KEY"
etcdctl --endpoints="$ETCD_ENDPOINTS" del "$ETCD_PREFLIGHT_KEY"
```

Runtime principal마다 encoded exact range `[ETCD_CANDIDATE_ROOT, rangeEnd)`에만
read/write permission을 줍니다. 검증한 server version과 attached lease에 대한
cross-principal revoke 거부 결과를 배포 기록에 남깁니다. 같은 range를 공유하는
principal은 서로 신뢰해야 하며 lease authorization contract를 증명할 수 없으면 별도
cluster를 사용합니다.

Shutdown과 cutover 전에는 campaign drain, protected work stop/join, caller client가
healthy한 동안 bounded same-elector `Resign`이 필요합니다. Official cleanup이
`client.Ctx()`에서 계속 막히면 shared client의 모든 사용자를 조정하고 caller-owned
client를 닫아 call을 join한 뒤 unresolved generation을 저장합니다. 별도의 healthy
diagnostic client로 exact range가 비었음을 증명합니다.

```bash
test "$ETCD_ACTIVE_CAMPAIGNS" -eq 0
test "$ETCD_PROTECTED_WORKERS" -eq 0
ETCD_EXACT_RANGE_COUNT="$(etcdctl --endpoints="$ETCD_DIAGNOSTIC_ENDPOINTS" get "$ETCD_CANDIDATE_ROOT" --prefix --count-only)"
test "$ETCD_EXACT_RANGE_COUNT" -eq 0
```

Cutover는 이 proof 뒤에만 etcd contender를 시작합니다. symmetric rollback은 protected
work와 모든 etcd contender를 멈추고 같은 exact range proof를 반복한 뒤 이전 provider를
복원하며 etcd contender가 0인지 확인합니다. Provider overlap에는 외부 fencing
authority가 필요합니다.

quorum recovery 중 minority에서는 campaign하지 않습니다. Majority를 복구하고 endpoint
Status와 linearizable roundtrip을 다시 실행한 뒤 retained generation을 모두 reconcile하고
restart gate를 엽니다. `IsLeader` sampling cadence는 `min(RenewInterval, 1s)`로 정하고 첫
true-to-false transition에 alert합니다. `ErrCommitUnknown`/`ErrCleanupPending`은
inventory하되 endpoint, key, lease, token, rendered error를 label로 사용하지 않습니다.

Dependency rollback은 runtime toggle이 아니라 review된 source change입니다.

```bash
git diff -- go.mod go.sum
git rm -r leader/etcd
# 다음 shared file에서 etcd registration/claim만 제거합니다.
# README.md README.ko.md leader/README.md leader/README.ko.md CHANGELOG.md
test -z "$(git grep -n 'leader/etcd' -- README.md README.ko.md leader/README.md leader/README.ko.md CHANGELOG.md)"
go mod tidy
make ci
```

이번 release가 추가한 provider registration과 implementation만 제거하고 unrelated
`leader`/module 변경은 보존합니다. etcd로 campaign하는 binary가 남아 있을 때는
destructive rollback을 실행하지 않습니다.

### Telemetry와 Promotion

Campaign wait duration, acquisition, timeout/cancellation, validation failure,
provider failure, `ErrCampaignInProgress`, `ErrCleanupPending`, cleanup duration,
resign retry, TTL fallback, takeover latency를 관측합니다. Confirmed, bare-context,
commit-unknown outcome은 분리합니다. Label은 bounded backend, operation, outcome,
sentinel category만 사용하며 identity, endpoint, token, rendered error는 label이나
log에 넣지 않습니다.

Canary는 최소 `max(15분, 10 * 최대 leader TTL)` 동안 실행하고 contention, renewal,
resign, takeover를 포함합니다. 다음 조건을 모두 만족할 때만 promote합니다.

- 새 validation failure와 unresolved cleanup-pending record가 모두 0입니다.
- Provider/resign failure와 campaign-timeout rate가 이전 stable window 대비 상대 20%와
  절대 1 percentage point 범위 안에 있습니다.
- Campaign-wait와 takeover-latency p95가 baseline의 1.2배 이하입니다.
- etcd가 아닌 provider의 모든 cleanup이 2 TTL 안에 bounded retry 또는 TTL
  fallback으로 끝납니다. etcd는 성공한 revoke 또는 linearizable exact-key/range
  absence proof가 필요하며, TTL only schedules another proof attempt입니다.
- PostgreSQL pool wait/statement p99가 `Lease-RenewInterval` margin 안에 있고,
  starvation에서 server-time expiry 전에 local leadership이 해제되며, controlled HA
  fencing/takeover exercise가 성공합니다.

Gate 위반, raw identifier/error 노출, goroutine/container leak, 2 TTL을 넘긴 cleanup
pending, 새 owner를 막는 lease가 하나라도 있으면 promotion을 hold합니다. Safety/redaction
위반이 있거나 두 번의 연속 5분 window 동안 회복하지 못하면 rollback합니다.

### Rollback 완료 조건

Binary rollback 전에 service shutdown context로 outstanding campaign을 취소하고 bounded
owner-aware resign을 시도합니다. Campaign goroutine과 renew traffic이 0이고, 모든 cleanup이
끝났으며 takeover probe가 성공해야 rollback 완료로 선언합니다. 남은 TTL 기록은 TTL
expiry를 cleanup으로 인정하는 provider에서만 충분합니다. etcd rollback은 성공한 revoke
또는 linearizable exact-key/range absence proof가 계속 필요합니다. etcd에서 TTL only
schedules another proof attempt이며 gate를 완료하지 않습니다. 기존 provider storage
format은 바뀌지 않았으므로 data migration rollback이 필요하지 않습니다. `leader/sql`
binary rollback에서는
`public.bluetape_leader_leases`와 grant를 유지합니다. 사용 중인 binary가 없어진 뒤 별도
review된 migration으로만 table을 drop하거나 rewrite합니다.
