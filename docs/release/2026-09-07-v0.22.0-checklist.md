## 릴리스 범위

`v0.22.0`은 milestone #34의 공간·지오코딩·그래프 기반 기능을 Go-native
경계로 배포한다.

- WGS 84 degree 좌표, antimeridian-aware bounds, Haversine 거리와 canonical
  lowercase Geohash
- 공개 테스트용 backend-neutral `graph/graphtest` conformance harness와
  digest-pinned Neo4j/Memgraph fixture에서 검증하는 `graph/neo4j` adapter
- SRID를 보존하는 PostGIS EWKB helper와 MySQL/MariaDB별 GIS mapping/query
- caller-owned reverse geocoding provider와 bounded Nominatim-compatible
  HTTP adapter
- caller-owned FalkorDB OpenCypher 및 remote Gremlin/TinkerPop adapter
- PostGIS, FalkorDB, TinkerPop의 digest-pinned Testcontainers fixture와
  MySQL/MariaDB image digest 고정

각 provider는 `context.Context`, caller-owned client/credential/lifecycle,
bounded payload/result, 명시적 capability와 redacted provider error 경계를
유지한다. 범용 spatial/graph abstraction, Nominatim 운영 정책과 downstream
consumer update는 포함하지 않는다.

## 리뷰와 Nightly 증거 계약

- Six independent lanes(performance, stability, security, operator/Ops,
  developer/API, user/caller)와 main integration review는 같은 exact head에서
  각각 `P0=0 P1=0 P2=0 P3=0`이어야 한다. 한 건이라도 남으면 PR 생성, merge,
  milestone 종료, promotion, tag와 Release를 모두 보류한다.
- Release Nightly는 workflow dispatch `scope=full`만 인정한다. Dispatch 전에
  `nightly-tests` active run이 없어 새 run이 concurrency
  `cancel-in-progress`로 기존 검증을 취소하지 않는지 확인한다.
- Run ID, `head_sha`, `event=workflow_dispatch`, input `scope=full`, 전체 run의
  terminal `success`를 기록한다. `Plan Nightly Scope`, `Smoke / lint`,
  `Testcontainers / full test pass`, `Race / Testcontainers` 네 job은 모두
  terminal `success`여야 하며 `skipped`, `cancelled`, 누락은 허용하지 않는다.
- Testcontainers와 race step log에서 `Attempt 1 failed` 또는
  `Attempt 2 failed`를 검색한다. 최종 step이 성공해도 내부 retry 실패가 있으면
  원인을 분류하고 release blocker가 아님을 증명하기 전에는 통과로 처리하지
  않는다. GitHub rerun이 있으면 모든 `run_attempt`과 이전 conclusion을 함께
  읽고 설명되지 않은 failure/cancellation을 허용하지 않는다.

- `git tag -s v0.22.0 <exact-main-sha>`로 signed annotated tag를 만들고,
  task-scoped `allowedSignersFile`에 principal과 expected public key만 기록해
  `git verify-tag --raw v0.22.0`이 expected principal/fingerprint로 성공해야
  한다. Trusted signer 파일이 없거나 결과가 다르면 tag push를 금지한다.
- Push 뒤 GitHub Git tag object의 `verification.verified=true`, `reason=valid`,
  tag object SHA와 dereferenced commit을 독립적으로 읽어 기록한다. Local
  verification과 GitHub verification 중 하나라도 실패하면 publication을
  금지한다.
- Local tag dereferenced commit, remote tag dereferenced commit과 fresh
  `origin/main`은 모두 같은 exact commit이어야 한다. GitHub Release는
  `tagName=v0.22.0`, `isDraft=false`, `isPrerelease=false`이고 같은 tag object를
  가리키는지 게시 직후 live read-back한다.

## 재실행과 복구

- PR 생성 또는 merge 결과가 모호하면 base/head 이름과 exact head SHA로 open 및
  merged PR을 live read-back한다. 하나의 matching PR, expected `mergedAt`과 merge
  SHA를 확인하기 전에는 생성/merge를 재시도하거나 다음 phase로 진행하지 않는다.
- Remote tag push 전에는 실패한 PR/branch 단계만 같은 exact head에서
  재검증하고 tag를 만들지 않는다.
- Local tag 생성 결과가 모호하면 먼저 local tag object type, annotation,
  signature와 dereferenced target을 읽는다. Expected signer와 exact `main` target이
  일치하면 재생성하지 않고 그 object를 사용한다. 불일치할 때에는 현재 시도에서
  새로 만든 unpushed tag임을 증명한 경우에만 삭제하고, 기존 또는 remote tag는
  덮어쓰거나 삭제하지 않는다.
- Remote tag push 뒤에는 tag를 이동하거나 재사용하지 않는다. 결함은 새
  corrective patch release로 처리한다.
- Milestone update/comment/close 또는 promotion mutation 결과가 모호하면 해당
  issue, milestone 또는 PR을 live read-back해 실제 상태를 확정하기 전에는
  재시도하거나 다음 phase로 진행하지 않는다.
- Tag push 결과가 모호하면 `git ls-remote --tags origin refs/tags/v0.22.0
  refs/tags/v0.22.0^{}`와 GitHub tag object/signature를 먼저 확인한다.
  Remote tag가 없다고 확정된 경우에만 새 CG-X01 뒤 동일 local tag object를
  재시도한다.
- GitHub Release 게시만 실패하면 재시도 직전에 새 CG-X01에서 exact
  `v0.22.0` target, 기존 Release absence, immutable remote tag object,
  dereferenced commit과 signer verification을 모두 다시 읽은 뒤 같은 body를
  게시하고 live body를 검증한다.
- Nightly 또는 CI가 실패하면 동일 exact head에서 원인을 진단한다. Head가
  바뀌면 이전 성공 증거는 폐기한다.
- Cleanup 전 branch마다 expected merge commit ancestry 또는 patch/tree
  equivalence, matching open PR 부재, 다른 worktree 미사용, remote ref 상태를
  확인한다. 새 CG-X01 뒤 task-owned ref/worktree를 개별 삭제하고 remote absence를
  read-back한다. 어느 증거든 모호하거나 cleanup이 실패하면 worktree, branch와
  recovery evidence를 보존한다.
