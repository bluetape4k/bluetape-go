## 릴리스 단계

1. Merge this release-prep branch to `develop` after the branch/PR authority and
   CI gate are explicitly approved.
2. Close milestone `0.19.0` only after the prep commit is on `develop` and a
   fresh milestone-close gate passes.
3. Open and verify the `develop -> main` release promotion PR with release
   scope, CI evidence, milestone state, and tag plan.
4. Merge the promotion PR after fresh merge approval and passing CI.
5. Create and push annotated tag `v0.19.0` on the verified `main` commit.
6. Create GitHub Release `v0.19.0` from the matching changelog section.
7. Update downstream Go consumers only when the release tag is live.

## 롤백 메모

Before a tag is pushed, close the release PR and delete only its temporary
branch if rollback is explicitly authorized. After a tag or GitHub Release,
use a corrective patch release unless an explicit retag plan is approved.
