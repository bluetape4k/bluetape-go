# 0.1.0 Foundation Research

## Milestone

0.1.0 - Foundation packages: core support, collections, goroutine helpers,
codecs/compression, Redis leader election, and shared test infrastructure.

## bluetape4k Evidence

- `bluetape4k-projects/bluetape4k/core`: support helpers, collection helpers,
  and codecs such as Base58, Base62, URL62, Base64, and Hex encoders.
- `bluetape4k-projects/io/io`: binary serializer and compressor abstractions,
  including gzip, zstd, lz4, snappy, deflate, bzip2, zip, and streaming
  compressor variants.
- `bluetape4k-projects/testing/testcontainers`: reusable integration-test
  fixture pattern.
- `bluetape4k-leader`: leader election core plus Redis, etcd, Kubernetes,
  Consul, Hazelcast, MongoDB, DynamoDB, and Zookeeper backends.

## Go Direction

Start with small, framework-free packages:

- `core`: validation, support, pointer/value helpers, codecs.
- `collections`: generic slice/map helpers only where Go stdlib is insufficient.
- `concurrency`: context-aware goroutine helpers, errgroup-style composition,
  bounded parallelism, and panic-to-error capture.
- `serialization`: safe binary serializer interfaces and compression wrappers.
- `testcontainers`: fixture conventions shared across Redis, PostgreSQL, and
  messaging services.
- `leader`: harden the existing Redis implementation and define compatibility
  rules.

## Dependency Candidates

- `golang.org/x/sync`: errgroup, semaphore, and singleflight primitives.
- `github.com/klauspost/compress`: actively maintained compression package.
- `github.com/pierrec/lz4`: LZ4 support.
- `github.com/redis/go-redis/v9`: Redis backend client.
- `github.com/testcontainers/testcontainers-go`: integration fixture runtime.

## Decision

0.1.0 should not be only leader election. It should establish the package
quality bar for bluetape-go: idiomatic Go APIs, small helpers with clear value,
safe serialization/compression defaults, and Testcontainers-backed proof.
