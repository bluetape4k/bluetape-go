# 0.7.0 Relational SQL Research

## Milestone

0.7.0 - relational SQL DSL 및 repository helper.

## bluetape4k 근거

- `bluetape4k-exposed`는 SQL을 숨기지 않으면서 relational access를 더 안전하게 만드는 repository, transaction,
  table/entity, dialect helper pattern을 제공한다.
- 기존 `bluetape-go` Testcontainers fixture는 PostgreSQL과 MySQL을 이미 덮으므로 SQL track은 real database smoke test를
  재사용할 수 있다.

## Go 방향

- SQL은 visible하고 inspectable하게 유지한다.
- runtime-first API와 plain Go value를 우선한다.
- #100이 가장 작은 안전 경로임을 증명하기 전까지 mandatory code generation은 기본적으로 거부한다.
- code generation이 필요하면 optional, isolated, reproducible, easy-to-diff 형태로 둔다.
- repository ergonomics, `context.Context`, transaction, explicit error, safe query construction에 집중한다.
- full ORM layer와 Kotlin Exposed clone은 피한다.

## Dependency Candidates

- `github.com/go-jet/jet`: type-safe SQL builder shape.
- `entgo.io/ent`: schema, field, edge, migration design reference.
- Bob, Bun, sqlc, Atlas, goqu, GORM은 #100의 comparison candidate로 남긴다.

## 결정

relational SQL은 backend service infrastructure의 foundation이므로 graph work보다 앞선다. #100이 최종 API와 dependency
recommendation을 기록한 뒤 implementation milestone은 0.7.0으로 이동한다.

## Issue 100 결과

#100은 runtime-first path를 선택한다.

- #317은 `database/sql` transaction 및 row mapping foundation을 구현한다.
- #318은 #317 landing 뒤 inspectable SQL builder와 repository prototype을 구현한다.
- #319는 optional sqlc/Jet generated-code workflow와 Atlas migration guidance를 문서화한다.

default package에서는 mandatory code generation을 계속 거부한다. ent, Bob, Bun, GORM, goqu,
JSON/encrypted/measured column, cache-backed repository, CTE, batch, schema metadata, dialect module은 base API 또는 concrete
consumer가 필요를 증명할 때까지 보류한다.
