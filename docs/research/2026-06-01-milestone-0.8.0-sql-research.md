# 0.8.0 Relational SQL Research

## Milestone

0.8.0 - Relational SQL DSL and repository helpers.

## bluetape4k Evidence

- `bluetape4k-exposed` provides repository, transaction, table/entity, and
  dialect helper patterns that make relational access safer without hiding SQL.
- Existing `bluetape-go` Testcontainers fixtures already cover PostgreSQL and
  MySQL, so a SQL track can reuse real database smoke tests.

## Go Direction

- Keep SQL visible and inspectable.
- Prefer runtime-first APIs and plain Go values.
- Treat mandatory code generation as rejected by default until #100 proves it
  is the smallest safe path.
- If code generation is needed, keep it optional, isolated, reproducible, and
  easy to diff.
- Focus on repository ergonomics, `context.Context`, transactions, explicit
  errors, and safe query construction.
- Avoid a full ORM layer and avoid a Kotlin Exposed clone.

## Dependency Candidates

- `github.com/go-jet/jet`: type-safe SQL builder shape.
- `entgo.io/ent`: schema, field, edge, and migration design reference.
- Bob, Bun, sqlc, Atlas, goqu, and GORM remain comparison candidates from #100.

## Issues

- Research: #100
- Epic: #101
- First implementation children from #100: #317, #318, #319

## Decision

Relational SQL belongs earlier than graph work because it is foundational
backend service infrastructure. The implementation milestone moves to 0.8.0,
after #100 records the final API and dependency recommendation.

## Issue 100 Outcome

#100 selects a runtime-first path:

- #317 implements `database/sql` transaction and row mapping foundations.
- #318 implements the inspectable SQL builder and repository prototype after
  #317 lands.
- #319 documents optional sqlc/Jet generated-code workflows and Atlas migration
  guidance.

Mandatory code generation remains rejected for the default package. ent, Bob,
Bun, GORM, goqu, JSON/encrypted/measured columns, cache-backed repositories,
CTE, batch, schema metadata, and dialect modules are deferred until the base API
or concrete consumers prove the need.
