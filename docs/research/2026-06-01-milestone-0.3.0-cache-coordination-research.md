# 0.3.0 Cache And Coordination Research

## Milestone

0.3.0 - Near cache, distributed locks, and rate limiting.

## bluetape4k Evidence

- `bluetape4k-projects/cache/cache-core`: common cache abstractions.
- `cache/cache-lettuce`, `cache/cache-redisson`, and
  `cache/hibernate-cache-lettuce`: Redis-backed cache and near-cache patterns.
- `infra/bucket4j`: token bucket and rate limiting concepts.
- `infra/redis`, `infra/lettuce`, and `infra/redisson`: distributed lock and
  Redis coordination helpers.

## Go Direction

- Define small cache interfaces and loader/stampede-protection patterns.
- Implement local cache adapters only when they add consistent bluetape-go
  behavior beyond dependency APIs.
- Implement Redis-backed near cache with Pub/Sub invalidation.
- Implement Redis distributed locks with owner tokens and TTL.
- Implement local and Redis token-bucket rate limiting.

## Dependency Candidates

- `github.com/dgraph-io/ristretto`: high-performance local cache candidate.
- `github.com/allegro/bigcache`: large in-memory cache candidate.
- `golang.org/x/sync/singleflight`: stampede protection.
- `github.com/redis/go-redis/v9`: Redis lock, near cache, and limiter backend.

## Decision

The value of bluetape-go here is coordination and consistent behavior across
local and Redis-backed variants, not another generic cache library.
