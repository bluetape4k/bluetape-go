# 0.10.0 Text Research

## Milestone

0.10.0 - Text search and tokenizer packages.

## bluetape4k Evidence

- `bluetape4k-text/text-search`: search functionality.
- `bluetape4k-text/tokenizer-core`: tokenizer abstractions and blockword
  request/response concepts.
- `bluetape4k-text/tokenizer-korean` and `tokenizer-japanese`: language-specific
  tokenization.
- `bluetape4k-text/lingua`: language detection integration.

## Go Direction

- Implement multi-pattern search and blockword masking first.
- Design tokenizer interfaces before choosing language-specific dependencies.
- Treat Korean/Japanese tokenization as research-heavy because dictionary,
  model, license, and binary-size tradeoffs matter.
- Language detection should be dependency-first unless a small Go-native option
  is clearly sufficient.

## Dependency Candidates

- Aho-Corasick and language detection package candidates need dedicated
  dependency review in #55.
- Standard library Unicode support should be used wherever possible for
  boundary handling.

## Issues

- Epic: #45
- Tasks: #52, #53, #54, #55

## Decision

Text search and masking are strong Go candidates. Full Korean/Japanese
tokenizers should not be committed until dependency quality and dictionary
maintenance are understood.
