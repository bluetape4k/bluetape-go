# 0.4.0 State And Workflow Research

## Milestone

0.4.0 - State machine and lightweight workflow primitives.

## bluetape4k Evidence

- `bluetape4k-projects/utils/states`: state-machine concepts.
- `bluetape4k-projects/utils/workflow`: sequential, parallel, conditional
  workflow primitives and work reports.
- Batch and leader examples show workflows guarded by leadership or scheduled
  execution.

## Go Direction

- `state`: finite state machine with states, events, guards, and transition
  errors.
- `workflow`: sequential, parallel, and conditional runners using
  `context.Context`.
- `workreport`: result tree shared by workflow and batch.
- Failure policy should be explicit: stop, continue, skip, retry, or aggregate.

## Dependency Candidates

- Prefer local implementation first. The target API is small and should avoid a
  heavy workflow engine dependency.
- Use `golang.org/x/sync/errgroup` where parallel workflow semantics match.

## Decision

Keep this layer lightweight. If a use case needs durable orchestration, it
belongs in a workflow engine or a later integration package, not 0.4.0.
