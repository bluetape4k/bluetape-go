# 0.5.0 Batch Research

## Milestone

0.5.0 - Batch processing with checkpoints and examples.

## bluetape4k Evidence

- `bluetape4k-projects/docs/superpowers/plans/2026-04-10-utils-batch-plan.md`
  describes reader/processor/writer, chunk loops, retry/skip policy, restart,
  checkpointing, workflow integration, and examples.
- `bluetape4k-exposed/utils/batch`: batch core and benchmark hub.
- `bluetape4k-leader/examples/batch-scheduler` shows leader-guarded batch
  scheduling.

## Go Direction

- `batch`: generic reader, processor, writer, job, step, and chunk loop.
- Retry and skip policies should reuse the resilience package where possible.
- Checkpoint store should be interface-first, with memory and file adapters
  before database adapters.
- Examples should connect batch with leader election for scheduler and
  migration workloads.

## Dependency Candidates

- Prefer local implementation for the core loop.
- Reuse `resilience` package for retry once 0.2.0 exists.
- Future stores may use Redis, PostgreSQL, or S3 depending on example needs.

## Decision

The first Go batch package should be a small library, not a Spring Batch clone.
Checkpoint semantics and restart tests are more important than feature breadth.
