# Issue #179 Locale Currency Mapping Lessons

## Context

Issue #179 expands `money.CurrencyByLocale` from a small manual region map to CLDR-backed current legal-tender lookup.

## Decisions To Preserve

- Use `golang.org/x/text/language` for BCP47 parsing and region validation.
- Use `golang.org/x/text/currency.Query(currency.Region(r))` for current tender lookup.
- Do not use `currency.FromTag` for this API because it can infer likely regions and would make language-only tags look valid.
- Require an explicitly supplied region; `ko`, `und`, and `en-001` stay invalid.
- Reject regions with zero current tender units or multiple current tender units using `ErrInvalidCurrency`.
- Preserve existing BCP47-like compatibility for `at-AT` by extracting the explicit region first and tolerating `language.ValueError` only after the region is valid.
- Use `en-QM` or `en-AQ` as no-tender fixtures; `aa-BB` is not a no-tender fixture because `BB` maps to Barbados and current `BBD`.

## Verification Pattern

Run the money package tests and the repo-local concurrency stress package together:

```bash
go test -count=1 ./money ./testing/concurrency
go test -race -count=1 ./money ./testing/concurrency
```

Keep `TestCurrencyByLocaleUsesGoroutineStressTester` when changing locale lookup behavior. It covers concurrent success and rejection paths without adding package-level caches or shared state.
