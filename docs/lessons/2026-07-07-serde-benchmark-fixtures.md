# SerDe benchmark fixture baseline

Issue #399는 runner나 recommendation 작업 전에 comparison contract를 정의해야 한다.
Cross-repo benchmark 작업은 payload, field naming, decimal/time handling,
invalid-input policy를 raw output 뒤에야 발견하면 쉽게 오해를 만든다.

## 교훈

- Fixture definition은 versioned contract로 취급한다. Go/Rust/JVM runner가 data를 낸 뒤
  기존 fixture를 바꾸기보다 `vN` fixture ID를 추가한다.
- Byte payload는 byte-oriented로 유지한다. Base64 wrapping은 explicit codec scenario에만
  속한다. 그렇지 않으면 object serializer가 일반 contract에 없는 hidden work를 하게 된다.
- Strict decode policy와 lenient decode policy를 분리한다. Unknown-field 또는 version drift
  result는 throughput winner가 아니라 policy evidence가 먼저다.
- Generated byte size는 raw output 옆에 보존한다. Command name과 fixture ID가 같아 보여도
  size drift는 benchmark를 무효화할 수 있다.
