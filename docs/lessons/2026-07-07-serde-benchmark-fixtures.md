# SerDe Benchmark Fixture Baseline

Issue #399 should define the comparison contract before any runner or
recommendation work starts. Cross-repo benchmark work becomes misleading when
payloads, field naming, decimal/time handling, and invalid-input policy are
discovered only after raw outputs exist.

## Lessons

- Treat fixture definitions as versioned contracts. Add `vN` fixture IDs rather
  than mutating an older fixture after a Go/Rust/JVM runner has emitted data.
- Keep byte payloads byte-oriented. Base64 wrapping belongs only in an explicit
  codec scenario, otherwise object serializers get hidden work that is not part
  of their normal contract.
- Separate strict and lenient decode policies. Unknown-field or version drift
  results are policy evidence first, not throughput winners.
- Preserve generated byte sizes next to raw outputs. Size drift can invalidate
  a benchmark even when command names and fixture IDs look unchanged.
