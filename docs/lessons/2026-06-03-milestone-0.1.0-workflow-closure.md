# Lesson: 0.1.0 Workflow Closure

## What happened

Milestone 0.1.0 delivered foundation code and merged PRs, but the workflow evidence was incomplete. The main misses were:

- design/spec/plan artifacts were not consistently written under `docs/superpowers`;
- Step 6-R code review evidence was not recorded before completion;
- issue/PR metadata checks for `milestone` and `assignee` were not enforced at creation time.

## What resolved it

0.1.1 was created as a retrospective quality closure milestone. The work backfilled research/spec/plan/review artifacts, ran a 7-tier review over the 0.1.0 foundation surface, and fixed the P1 JSON trailing-data finding found during review.

## Rule for next time

For every milestone issue/PR:

1. Create or verify the milestone before issue/PR creation.
2. Assign issue/PR to `debop` immediately.
3. Set the milestone immediately.
4. Run metadata gate immediately after creation:

```bash
gh issue view <number> --json milestone,assignees
gh pr view <number> --json milestone,assignees
```

If either field is missing, stop the workflow and fix metadata before continuing to implementation or merge gates.
