# 0.22.0 공간·지오코딩·그래프 통합 구현 교훈

일자: 2026-09-07
이슈: #547, #550, #551, #552, #554, #561
마일스톤: 0.22.0

## 배경과 결정

다섯 구현 이슈를 한 번의 PR/squash merge로 전달하되, 각 backend와 provider는
독립적인 Go package, 테스트, README/README.ko, fixture와 오류 계약을 유지했다.
`geo`, `graph`, `sqlkit` core에는 공통 `SpatialStore`/`GraphClient`/dialect
abstraction을 넣지 않았다. 호출자가 client, credential, HTTP policy, lifecycle을
소유하고 adapter는 bounded 입력·결과·진단과 명시적인 cancellation 경계만 제공한다.

## 구현 중 발견한 함정

- MySQL spatial constructor는 WGS84 좌표의 axis order를 명시하지 않으면 입력이
  뒤집힐 수 있었다. `axis-order=long-lat`을 생성·조회 SQL에 고정하고 실제 MySQL
  8.4 fixture에서 round-trip을 확인했다.
- MariaDB는 binary bind argument를 `ST_PointFromWKB`/`ST_PolyFromWKB`에 바로
  넘길 때 driver 표현에 따라 해석이 달라졌다. `CAST(? AS BINARY)`를 boundary에
  두고 MariaDB fixture에서 point·distance·MBR을 확인했다.
- FalkorDB RESP 통계는 outer single-element array를 포함할 수 있었다. parser는
  해당 envelope을 허용하되 column/row/통계 payload와 row limit은 계속 검증한다.
- TinkerPop `elementMap` 결과는 `map[interface{}]interface{}`와 중첩된 `IN`/`OUT`
  endpoint map으로 반환될 수 있었다. Gremlin 변환 경계에서 map key를 문자열화하고
  endpoint를 명시적으로 추출했으며, 원격 API에 서버-side context cancellation이
  있다고 주장하지 않고 local checkpoint와 result stream close만 보장한다.
- Gremlin 결과의 outer channel 상한만으로는 반사된 slice/array와 중첩 path 값의
  확장을 제한할 수 없었다. `94aa3ef`에서 재귀 확장 깊이와 nested value 상한을
  추가하고 회귀 테스트로 고정했다.
- `revive`, `errcheck`, `staticcheck`는 구현이 동작해도 Go doc 시작 토큰,
  deferred close와 논리식 형태를 별도 계약으로 검사했다. `d956c97`에서 모든
  lint 결과를 `0 issues.`로 맞추고 전체 gate를 재실행했다.
- TinkerPop image는 처음 local cache에 없어 fixture가 시작되지 않았다. image
  pull을 별도로 수행한 뒤 digest-pinned fixture와 conformance를 재실행했다. CI는
  항상 registry 접근·pull 실패를 skip이 아닌 실패 증거로 남겨야 한다.
- PR #738의 첫 coverage run에서는 port listening만 통과한 직후 Gremlin-Go
  handshake가 실행되어 `TestConformance` factory가 실패했다. TinkerPop log의
  `Channel started at port 8182.`를 추가 readiness 신호로 고정한 `7053dae` 뒤
  동일 startup/conformance 경계를 로컬 5회 반복해 모두 통과했다. 두 번째 run
  `34047689484`는 coverage까지 통과했지만 serial `make race`가 25분 job 제한을
  초과해 취소되었다. 최신 head 로컬 전체 race는 586초에 통과했으므로, cold-cache
  Docker fixture 실행 여유만 늘리도록 CI job timeout을 40분으로 조정했다.

## 적용한 재발 방지 규칙

- PostGIS는 EWKB에 SRID를 명시하고 `ST_DWithin`과 GIST/bounding-box SQL을
  engine package 안에서 함께 검증한다. MySQL과 MariaDB는 공통 SQL로 합치지 않고
  각자의 SRID, axis-order, constructor, index 계약을 유지한다.
- Nominatim adapter는 기본 public endpoint를 만들지 않는다. 명시적인 absolute URL,
  식별 가능한 User-Agent, bounded body, context cancellation, caller-owned
  rate-limit/cache와 attribution을 요구한다. bulk geocoding과 암묵적 retry는
  범위에서 제외한다.
- FalkorDB는 caller-owned `redis.UniversalClient`를 닫지 않는다. Gremlin은
  caller-owned executor/connection과 내부 remote connection을 구분하고, 모든
  result stream은 bounded limit·close·redacted provider error를 갖는다.
- Testcontainers image는 이름과 digest를 함께 고정하고 readiness와 termination을
  검증한다. Docker-backed 명령은 PostGIS → MySQL → MariaDB → FalkorDB → TinkerPop
  순으로 직렬 실행한다.
- public API 변경에는 Go doc, English/Korean README, example과 fake-first 테스트를
  함께 둔다. 새 dependency는 공식 FalkorDB Go client와 Gremlin-Go로 제한하고
  `go mod tidy`로 module graph를 고정한다.

각 slice에서 `go test`, `go test -race`, `go vet`, `git diff --check`를 실행했고,
PostGIS·MySQL·MariaDB·FalkorDB·TinkerPop fixture 테스트는 같은 작업에서 직렬로
통과했다. 현재 구현 HEAD에서 `make fmt-check`, `make tidy-check`, `make vet`,
`make lint`, `make test`, `make race`, `make ci`도 통과했으며 Docker container는
각 단계 종료 후 비어 있음을 확인했다. PR #738의 첫 exact-head coverage run은
readiness gap으로 실패했고 `7053dae`에서 보정했다. 두 번째 run은 race job timeout으로
취소되어 CI timeout을 40분으로 보정했으므로, 수정 head의 원격 CI와 review/thread
read-back, merge와 release는 이 lesson 작성 시점의 후속 gate다.

## 후속 경계

Neptune/AGE/cloud credential, embedded TinkerGraph, 대량 Nominatim, 공통 graph
repository/session/query DSL과 GIS topology/projection은 이번 milestone에 넣지
않는다. 다음 변경은 이 독립 경계를 유지하고, 새 backend를 추가할 때 먼저 해당
protocol의 fixture와 오류·cancellation 계약을 증명해야 한다.
