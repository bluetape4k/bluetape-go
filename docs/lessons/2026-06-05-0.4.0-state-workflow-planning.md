# 0.4.0 State And Workflow Planning Lessons

Issue: #135
Milestone: 0.4.0

## Lesson

Start a new Go milestone by converting Kotlin module evidence into a small
Go-first package split before implementation begins. For 0.4.0, the useful
split is `state`, `workreport`, and `workflow`, with Kotlin DSL, coroutine,
reactive, and Virtual Thread layers treated as out of scope.

## Applied Guardrails

- `state` remains independent so finite state machine work can land first.
- `workreport` owns statuses and failure policy before runners consume it.
- `workflow` composes ordinary `context.Context`-driven work functions.
- Stress/cancellation coverage and compile-checked examples are tracked as
  milestone issues instead of optional cleanup.
- Package READMEs and diagrams follow API stabilization rather than preceding
  it.
