# Issue #517 통합 lesson

## 결정

AWS provider는 SDK 호출을 감싸는 얇은 adapter로 유지하고, config·credentials·
IAM policy·retry·timeout·pool·refresh·global registry는 caller/operator에게
남긴다. 서비스별 payload 한도와 cancellation 경계를 SDK dispatch 전에
검사해야 하며, 성공 응답 안의 item-level rejection도 오류로 surface해야
한다.

## 재사용할 규칙

- SQS/S3 payload는 aggregate bytes와 object digest를 한 번만 계산하고,
  cancellation이 side effect 뒤에 오면 orphan/receipt 상태를 명시적으로
  반환한다.
- CloudWatch Metrics/Logs는 finite/range/time-window/span을 preflight하고,
  partial acceptance에서는 거부 index만 재시도한다. sequence token을
  전역 직렬화 가정으로 되살리지 않는다.
- S3 Vectors는 AWS 문서의 Put/Get/dimension/metadata/request limit을 코드와
  README에 함께 고정한다. UTF-8 문자는 byte 수와 character 수를 구분하며,
  caller-owned metadata/filter는 SDK 호출 중 변경하지 않는다.
- secret/token/error에는 payload를 넣지 않고 `%+v`, `%#v`, `Stringer`,
  `GoStringer` 경로를 모두 redaction 테스트한다.
- fake-first client는 필요한 메서드 subset만 주입하고 request를 deep-copy하며,
  cancellation before/after와 typed-nil을 검증한다. live AWS 테스트를
  local green의 전제로 만들지 않는다.

## 검증에서 배운 점

PR branch가 base보다 뒤처지면 merge를 시도하지 말고 rebase 후 exact head CI를
다시 받아야 한다. 충돌 해결 뒤에는 README index뿐 아니라 `go.mod` 정렬도
`go mod tidy`로 재검증해야 한다. 이번 다섯 PR은 각각 exact-head CI PASS 후
squash merge되었고, 최종 `develop`은 `c59dfab`에서 origin과 일치한다.

macOS Colima에서 95개 package를 한 번에 Testcontainers로 실행하면 기존
Redis/Postgres/Mongo/etcd/Kafka fixture가 host-port forwarding 또는 짧은
concurrency timeout으로 간헐 실패할 수 있다. `TESTCONTAINERS_REUSE_ENABLE`
및 `TESTCONTAINERS_RYUK_DISABLED`를 명령 단위로 확인하고, 변경 package와
문제 fixture를 별도 프로세스로 순차 실행해 코드 회귀와 환경 경합을
분리한다. 전체 일괄 실패를 green으로 기록하지 않으며, 단독 재현 결과와
실패한 비변경 package를 함께 남긴다.

## 다음 변경자를 위한 지침

새 provider가 observability signal을 추가하면 `$bluetape-go-patterns`의
batching/order/cardinality/deprecation 표와 service-specific bound를 먼저
채운다. 운영자가 live endpoint와 retry 정책을 결정할 수 없는 상태에서는
새로운 hidden goroutine, cache, credential loader, global logger를 추가하지
않는다. merge·tag·release 전에는 항상 fresh exact-head metadata와 CI를
다시 읽고, cleanup 전에는 merged ancestry와 bundle recovery를 확인한다.
