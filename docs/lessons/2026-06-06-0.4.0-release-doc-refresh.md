# 0.4.0 Release Doc Refresh

Before tagging a milestone release, refresh repo-facing documents after the
epic and GitHub milestone are already closed.

The useful pattern is:

- keep `CHANGELOG.md` under `Unreleased` until the actual release PR/tag;
- update root README status from active development to closed-milestone release
  preparation;
- update `WIP.md` from issue closure to the release queue;
- update `docs/release/release-guide.md` from the previous release plan to the
  target release plan.

For future releases, run the doc refresh after milestone closure and before the
`develop` to `main` release PR. This keeps release docs current without
pretending the tag already exists.
