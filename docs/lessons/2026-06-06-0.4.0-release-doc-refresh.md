# 0.4.0 Release Doc Refresh

milestone release를 tag하기 전에는 epic과 GitHub milestone이 이미 closed된 뒤에
repo-facing document를 refresh한다.

유용한 pattern은 다음과 같다.

- 실제 release PR/tag 전까지 `CHANGELOG.md`는 `Unreleased` 아래에 유지한다.
- root README status를 active development에서 closed-milestone release preparation으로
  바꾼다.
- `WIP.md`를 issue closure에서 release queue로 바꾼다.
- `docs/release/release-guide.md`를 이전 release plan에서 target release plan으로
  갱신한다.

향후 release에서는 milestone closure 이후, `develop` to `main` release PR 전에 doc
refresh를 실행한다. 이렇게 하면 tag가 이미 있는 것처럼 꾸미지 않으면서 release
docs를 최신으로 유지할 수 있다.
