# 0.4.0 Stress Cancellation Gate

Issue #136 is a milestone gate, not a new helper package.

The useful closure pattern is:

- implement package-local stress and cancellation tests inside the owning issue;
- after dependent packages merge, add one milestone gate matrix that maps each
  acceptance criterion to concrete tests and race commands;
- keep heavy soak tests and benchmark loops out of the release gate unless an
  issue explicitly makes them acceptance criteria.

For future milestones, create the gate issue early, reference it from child
issue bodies, and close it only after all dependent packages are merged on
`develop`.
