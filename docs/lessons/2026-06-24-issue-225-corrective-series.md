# Lessons: Issue 225 Corrective Series Closure

Issue: #225
Date: 2026-06-24

- A closure audit should separate corrective blockers from future roadmap
  priority labels. Open P1/P0 future issues are not automatically P1/P0
  blockers for the current milestone.
- Keep source-parity decisions tied to issue numbers. Otherwise deferred work
  becomes invisible after the implementation slices merge.
- Record explicit non-goals for JVM, framework, and DSL-shaped source behavior
  so later agents do not re-litigate Kotlin-to-Go API cloning.
- Documentation-only closure still needs fresh repository gates when the report
  claims release readiness.
